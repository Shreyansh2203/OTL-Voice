# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| 1.x | ✅ |
| < 1.0 | ❌ |

## Reporting a Vulnerability

If you discover a security vulnerability in OTL-Voice, please report it responsibly.

**Do NOT** open a public GitHub issue for security vulnerabilities.

### How to Report

1. Email: [main.doga@gmail.com](mailto:main.doga@gmail.com) with subject "OTL-Voice Security Vulnerability"
2. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

### Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial assessment**: Within 7 days
- **Fix release**: Within 14 days (critical), 30 days (non-critical)

### Security Measures

- **Secret generation**: `provision.py` creates SESSION_SECRET_KEY / ADMIN_API_KEY / readiness_token — never printed
- **Sensitive field scrubbing**: Sentry events scrub `authorization`, `cookie`, `token`, `jwt`, `password`, etc.
- **Session management**: Redis-backed or in-memory (demo only)
- **SAST**: CodeQL on every push
- **Container scan**: Trivy image scan in CI
- **Type safety**: mypy on 61 backend files
- **Authenticating proxy**: TLS termination + IdP in production

### Secret Management

- Secrets are generated by `deploy/provision.py` and stored in `.env`
- `.env` is gitignored; `.env.example` contains only placeholders
- Never commit real credentials, tokens, or private keys

### Disclosure Policy

- Vulnerabilities are disclosed after a fix is released
- Credit is given to the reporter (unless they prefer anonymity)
- Public disclosure timeline: 90 days after fix release
