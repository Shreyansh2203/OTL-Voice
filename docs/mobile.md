# PWA and mobile builds

## Web/PWA

The production frontend is an installable PWA generated by `vite-plugin-pwa` and Workbox. It has an app shell, manifest, icons, and a service worker. API calls are deliberately excluded from the service-worker fallback so authentication, assignments, chat, speech, and timecard writes always reach the server.

Install it from a supported browser's “Install app”/“Add to home screen” flow. A PWA install does not make the application offline-capable: a network is still required for login and all business operations.

## Capacitor prerequisites

- Node 22 and pnpm 12.6.0.
- Android Studio, Android SDK, JDK, and a configured emulator/device for Android.
- Xcode, an Apple developer account, CocoaPods, and a configured device/simulator for iOS.
- A reachable HTTPS backend and a valid TLS certificate. Mobile operating systems may reject plaintext or self-signed endpoints outside a controlled development setup.

## Build

Install dependencies from the repository root:

```bash
pnpm install --frozen-lockfile
```

Build the web/PWA bundle:

```bash
pnpm --dir frontend run build
```

For a native bundle, set the API origin explicitly:

```bash
VITE_API_URL=https://otl.example.com pnpm --dir frontend run build:mobile
```

The script runs the TypeScript build, Vite build, and Capacitor sync. It fails if `VITE_API_URL` is missing, preventing an accidental localhost production bundle.

Open the native projects with:

```bash
pnpm --dir frontend run cap:android
pnpm --dir frontend run cap:ios
```

Native project files and signing identities are platform-specific and must be reviewed before distribution. The repository does not create an Android keystore, Apple provisioning profile, App Store Connect record, or push-notification service.

## Mobile security checklist

- Use HTTPS/WSS and a publicly trusted certificate.
- Do not ship a service-account credential, OCI key, or shared `AUTH_PASSWORD` in the app bundle.
- Keep OIDC/native browser authentication and cookie behavior aligned with the web deployment; test cookie persistence and logout on each OS.
- Request microphone permission only at the point of use and explain the processing path. Disable or clearly disclose browser speech fallback.
- Protect screenshots, app switcher snapshots, backups, and crash logs. Android backup and iOS shared-container settings must be reviewed for session data.
- Test expired sessions, network loss during voice capture, duplicate taps, and retry after an app restart.
- Keep the idempotency request ID stable for a reviewed row across retries; the server-side SQLite store is authoritative.

## Release validation

Before a store release, run the full web test matrix, a device build, and a manual smoke test covering login, assignment loading, one non-production timecard review, rejection/cancellation, retry, logout, microphone denial, and update installation. Record the app version and backend image digest together.
