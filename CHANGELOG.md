## 1.0.0

Baseline release. This entry is a **seed**, not a reconstruction of a shipped
tag: the repository had no Git tags at the time it was written, so there is no
release date to record. The 132 commits that preceded it are summarised below
from their commit subjects; the authoritative per-commit record is
`git log --oneline` on `main`, and the original descriptions are in
`git log`.

### What the project is

An installable React/Vite PWA and FastAPI service that captures Oracle Fusion
Cloud Time and Labour hours from a shift description in plain language or by
voice, resolves the employee's real Fusion assignments, streams an OCI
Generative AI and Speech response, and submits a reviewed, server-validated
timecard. It is a single origin: the PWA is served by the same
TLS-terminated service that holds the API, over an HttpOnly session cookie.

### Security and correctness work in this history

- Closed a rate-limit bypass and an idempotency-key replay hole that could
  duplicate a timecard write.
- Made the idempotency lease an independent crash-recovery window so a crashed
  write cannot block its `requestId` for the full 24h TTL.
- Closed Sentry redaction gaps, compared secrets as bytes, and added
  credential-scrubbing tests for both.
- Recorded the precise idempotency lease semantics in the documentation, not an
  approximation.
- Fixed a dead end in the timesheet retry flow: the client now follows the
  server's documented retry contract instead of surfacing a 24h dead end.
- Gave the Web Audio worklet its real sample rate and made it refuse a dead
  audio context rather than reporting a silent success.
- Derived the assistant's current date from the business timezone
  (`APP_TIMEZONE`) rather than the host, and made it work on a bare Windows
  workstation.
- Made the development runner's teardown immune to a mid-drain signal.

### Delivery and supply chain

- Pinned every GitHub Action to a full 40-character commit SHA with the release
  tag as a trailing comment.
- Added `pip-audit` and dependency review as merge gates, and published the
  versioned GHCR image with SBOM and provenance plus a high/critical scan.
- Blocked mutable image tags and the `latest` tag in both the publish and
  deployment paths.
- Anchored release-please and hardened the Ansible deployment handoff.
- Raised the backend coverage gate from 65% to 80% and the frontend coverage
  thresholds, in both cases backed by new tests rather than exclusions.

### Testing, accessibility, and documentation

- Added a strict TypeScript invocation over frontend test files so a test-only
  type error cannot hide behind application tsconfig exclusions.
- Gave every view a focus ring that is actually visible, and raised the warning
  badge contrast to a 5.81:1 ratio that passes WCAG AA.
- Made the E2E gate deterministic and bounded it to the Chromium, Firefox, and
  WebKit matrix, surfacing Playwright failures as job annotations.
- Added `CONTRIBUTING.md` and `SECURITY.md`, cross-linked the documentation
  map, and verified that every relative link and anchor resolves.
- Pointed the documentation at the single source of truth for each enforced
  threshold instead of restating config values in prose.
